# PROPS

**Status:** Current · **Last updated:** 2026-09-28 · **Verified against:** the props commit

## What happens in the game

Office furniture is loose: chairs, desks, monitors, filing cabinets and the copier. Walk into a chair and it shoves along; a blast throws everything nearby across the room, the furniture as well as the players. You can stand on a desk and climb onto it like any ledge. Furniture that has stopped costs nothing until something disturbs it again.

## Who owns what (AGENTS.md §3)

| Thing | Owner | Synced | Rate |
|---|---|---|---|
| Every prop's motion | **Host.** Only the host runs prop physics | Position and rotation, host → everyone, via FishNet NetworkTransform | Only while moving, every 2nd tick (30/s) |
| Which props exist | Host spawns them at the template markers after the towers build | FishNet spawn message per prop, once | On join |
| Throwing a prop | Host only, from the same blast that throws players | Arrives as motion | On hit |

On clients a prop is a **kinematic** body that follows the host's positions. It still blocks and shoves the local player, so collisions look right; it just cannot be moved by the client itself.

**The known trade:** a client walking into a chair is blocked until the host reports the chair moved, then the client's body is corrected forward by a few centimetres. FishNet smooths that. It was chosen over predicting every prop on every client, which would send every prop's state every tick (the GDD's bandwidth risk). If pushing furniture feels sticky in tests, the next step is to let clients simulate props locally and blend toward the host, not to predict them.

Bandwidth: sleeping props send nothing. A blast moving 15 props for two seconds sends about 15 × 40 B × 30/s ≈ 18 KB/s to each client for those two seconds, then stops.

## Designer-authored vs runtime-derived (AGENTS.md §4)

**Authored:** each prop prefab's size, mass and throw resistance; where markers sit in the floor templates; the blast's furniture throw speed on `BlastProfile`.
**Derived:** which prop instances exist and where they are now.

## Level rules

- **Cap: 16 props per floor**, the locked door included (it uses a `PropMarker` and is spawned the same way, with no physics; see TOWER.md). The GDD asks for a fixed cap; this is it, enforced by whoever places markers (the greybox tool keeps well under it). Raise it only with a profiler open.
- Props live on the **Prop** layer (7). They count as ground for the player, so desks are climbable and standable.
- Heavy set dressing that should never move (the board table, the reception desk, glass walls) stays static geometry in the template, not a prop.

## Scripts

Under [Assets/_Project/Scripts/Props/](../../Assets/_Project/Scripts/Props/):

- `Prop.cs`: on the prop prefab. Makes the body kinematic everywhere but the host; carries the throw resistance. `Throw(velocityChange)` is host-only.
- `PropMarker.cs`: on floor templates. Says which prop prefab goes here. Nothing else; it is invisible in play.
- `PropSpawner.cs`: on the `Tower` object. When the host has built the towers, spawns a networked prop at every marker; despawns them all if the towers rebuild.

Prop prefabs are in `Assets/_Project/Prefabs/Props/`, generated by the greybox tool (Chair, Desk, Monitor, Cabinet, Copier) until an artist authors real ones. Templates carry markers instead of static furniture wherever furniture should move.

## Known limitations

- No ragdoll: a desk hitting a player shoves them through physics but does not knock them down. Ragdoll is its own task.
- No far-floor freezing yet. Unity puts still props to sleep on its own, which is enough at this scale; add freezing only if a profiler shows otherwise.
- Props do not break, and nothing is destructible yet; pre-broken panels are a separate system.
- Late joiners get every prop's current pose once, then updates; a prop mid-flight at join may pop.
